# AdventureTogether - Feature Inventory

This document serves as the single source of truth for all implemented and planned features in AdventureTogether. Every architectural enhancement or feature addition must maintain backward compatibility with previously listed features and update this ledger accordingly.

## Feature Registry

| ID | Feature Name | Module | Status | Description & Acceptance Criteria |
|---|---|---|---|---|
| **FEAT-001** | Monorepo Architecture & Scaffolding | Core / Deploy | Completed | Modular folder structure (`frontend/`, `backend/`, `deploy/`, `documentation/`) with zero Redis overhead, PostgreSQL/PostGIS spatial persistence, and unified containerization. |
| **FEAT-002** | Event Lifecycle & Bounding Perimeter | `apps.events` | Completed | Host configuration of scavenger hunt events with title, start/end windows, custom hashtags, and GeoJSON bounding perimeter polygon enforcement. |
| **FEAT-003** | Team Management & Join Codes | `apps.teams` | Completed | Participant team creation and join-code mechanism enabling cooperative groups during quests. |
| **FEAT-004** | Geospatial Quest Builder & Validation Rules | `apps.quests` | Completed | Interactive host interface to draw quest target zones (points, polygons) and set OSM tag criteria, Wikimedia photo categories, and Wikidata targets. |
| **FEAT-005** | Foreground Geolocation & Privacy Matrix | `apps.locations` | Completed | Foreground-only GPS tracking utilizing HTML5 Geolocation and Page Visibility API with privacy tiers (`nobody`, `team`, `quest`) and 20-minute decay retention. |
| **FEAT-006** | Mobile Mapping Deep Linking | Frontend Composables | Completed | One-tap deep link generation for `streetcomplete://` and `everydoor://` pre-centered on active GPS coordinates. |
| **FEAT-007** | Multi-Platform Submission Harvester | `apps.submissions` | Completed | Overpass-based OSM harvester (`osm_tags`), OSM Notes, OpenHistoricalMap, Wikimedia Commons (real uploader and category), Wikidata (`wikidata_entry` and `wikidata_statement`) and GitHub (`oss_contribution`). Dispatches only the platforms an event's active quests need, returns per-platform stats, and logs errors by exception class so endpoint URLs never leak. Requires `OVERPASS_URL` (no public fallback). See `documentation/harvesters.md`. |
| **FEAT-008** | Host Verification Dashboard & Diffs | `apps.submissions` | Completed | Host portal displaying ingested submissions, tag/JSON diff visualizers, external proof links, and verification approval toggles. |
| **FEAT-009** | Ansible Deployment & VM Security Hardening | `deploy/ansible` | Completed | Production Ansible playbooks configuring UFW firewalls, SSH hardening, non-root execution, PostGIS backups, and Dockerized orchestration. |
| **FEAT-010** | Comprehensive Documentation & Guides | `documentation/` | Completed | End-user manuals and developer API documentation detailing architecture, endpoints, and deployment procedures. |
| **FEAT-011** | Simulated GPS Position (testing aid) | Frontend Composables | Completed | Dev-only override of the browser Geolocation API via `?lat=&lng=` query params, persisted in `localStorage`, with a header badge and clear control on the event map. Ignored in production builds unless `VITE_ALLOW_SIMULATED_GPS=true`. See `documentation/local_setup.md`. |
| **FEAT-012** | Quest Progress & Counted Quests | `apps.submissions` / `apps.quests` | Completed | `QuestProgress` per team and quest; `count` sums `element_count` of verified submissions and points are awarded once when `validation_rules.target_count` is reached, revoked if it drops below. Optional per-quest `window_start`/`window_end`, new criteria types (`location_checkin`, `osm_notes`, `ohm_feature`, `wikidata_statement`, `oss_contribution`, `street_imagery`; harvesters implemented except `street_imagery` (stretch)). Exposed via `GET /api/teams/<id>/progress/` and `GET /api/events/<id>/leaderboard/`. |
| **FEAT-013** | Conference Session Linkage | `apps.events` / `apps.quests` | Completed | Events take an optional pretalx/frab `schedule_url`; `GET /api/events/<id>/sessions/` returns its talks as a flat, 10-minute-cached list (400 when unset, 502 on fetch failure). Quests carry an `inspired_by` object `{code, title, speakers, start, room, track, url}` naming the session that inspired them. |
| **FEAT-014** | Contributor Platform Usernames | `apps.teams` | Completed | Team members can record optional `osm_username`, `wikimedia_username`, and `github_username` when joining (`POST /api/teams/join/`), returned on memberships, so harvesters can credit edits to the right team. |
| **FEAT-015** | GPS Check-in Quests | `apps.locations` / `apps.submissions` | Completed | `location_checkin` quests auto-verify from foreground location pings within `radius_m` of a point or inside a polygon, optionally after `min_minutes` in range, during the quest window. Evidence is a `checkin` submission; points flow through QuestProgress; a host revocation sticks. The ping response reports in-range check-ins and `GET /api/locations/checkins/` lists them. |
| **FEAT-016** | Event Seeding & FOSS4G NA 2026 Fixture | `apps.events` | Completed | `manage.py seed_event <file.json> [--schedule-json PATH] [--replace-quests]` upserts an event (by slug), its quests (by title) and teams (by name) in one transaction, validating GeoJSON and quest-in-perimeter; code-only `inspired_by` entries are expanded from a pretalx/frab schedule. Ships `backend/fixtures/foss4gna_2026.json` (28 quests) and an offline schedule snapshot. See `documentation/seeding_events.md`. |
| **FEAT-017** | Harvest Scheduling & Commands | `apps.submissions` | Completed | `manage.py setup_schedules` registers idempotent Django-Q2 schedules: `harvest_all_active_events` every 5 min (events whose window ±1 day contains now) and `cleanup_expired_pings` every 10 min. `manage.py harvest_event <id> [--dry-run]` runs one harvest and prints stats as JSON. `scripts/e2e_smoke.py` exercises the whole flow against a running backend. |
| **FEAT-018** | Quest Panel, Progress & Leaderboard UI | Frontend | Completed | Event map sidebar lists every active quest with type icon/label, points, team progress bar (count/target, done state), quest window, "Inspired by" session line with link and "Show on map"; Polygon/MultiPoint targets drawn as type-coloured outlines; leaderboard (top 5, own team highlighted, 30 s poll) also on home-page cards; check-in banner and card state from ping responses and the check-ins endpoint; participant self marker; phone layout stacks the map above the sidebar; join form collects OSM/Wikimedia/GitHub usernames; verification page shows new platform badges, element counts, contribution time and team progress. |
| **FEAT-019** | Quest Builder for All Quest Types with Session Picker | Frontend | Completed | Builder covers every criteria type (nine at the time, eleven with FEAT-021/022) with descriptions and per-type rule inputs composing `validation_rules` to the backend contract; optional quest window; "Inspired by" picker filtering `/sessions/` by title or speaker with manual fallback; point target or whole event area; `street_imagery` saved inactive; existing quests listed with delete-with-confirm. |
| **FEAT-020** | Value Scoring (Per-Bucket Points & Extreme Bonus) | `apps.submissions` / Frontend | Completed | Optional `validation_rules.scoring` on any quest type: `value` (`source` `"description"` or `"tag:<key>"`, regex `pattern`, `kind` `year`/`number`; years outside 1600..next year rejected) is read into `Submission.extracted_value` at harvest time (per-element values in `diff_payload.extracted_values`, representative = extreme); Commons harvester captures `extmetadata` description/object name. `per_bucket` pays points per distinct bucket (`floor(v/size)*size`) of a team's verified values; `extreme_bonus` (min/max) goes to the team(s) holding the extreme, ties share, and moves between teams. `QuestProgress.awarded_points` (plus `buckets`, `best_value`) holds completion + bucket + bonus points, team score moves by its delta, quest deletion revokes it. Hosts correct values via `verify` `extracted_value`; `GET /api/quests/<id>/standings/`. Builder "Value scoring (optional)" section, quest panel standing ("Decades found: 1920s, 1950s", bonus holder), inline value edit on the verification page. Seeded quest "Stamped in Sacramento". See `documentation/quest_types.md`. |
| **FEAT-021** | Mangrove Reviews Quests | `apps.submissions` / Frontend | Completed | `mangrove_review` quests (platform `mangrove`): one `GET {MANGROVE_API}/geo` bbox request per run over the quests' areas; a review counts when its `geo:` subject is inside the quest area, `iat` is in the window, the opinion has the hashtag (`require_hashtag`, default true) and at least `min_opinion_chars` characters, and optionally `rating >= min_rating`. Payload read from `payload` or decoded from the JWT. `external_id` `{signature}/q{quest}`, opinion stored as `text` for value scoring. Credited by nickname matched against `display_name` first (participants set their Mangrove nickname to their display name). Builder rule block, "Mangrove Reviews" tool. Seeded quest "Rate it on Mangrove". See `documentation/quest_types.md`, `harvesters.md`. |
| **FEAT-022** | MapRoulette Quests | `apps.submissions` / Frontend | Completed | `maproulette_task` quests (platform `maproulette`): `GET {MAPROULETTE_API}/tasks/box/...?tStatus=` over the quests' areas (200 a page, up to 20 pages); tasks count when their status is in `statuses` (default fixed/already fixed), `mappedOn` is in the window, the point is in the quest area and, optionally, the challenge is in `challenge_ids`. One `GET /task/{id}` per new or changed task (`detail_lookups` stat); attribution from the OSM changeset when known (honours `require_hashtag`, default false), else the completing user's OSM name (`/user/{id}/public` `osmProfile.displayName`), matched against `osm_username`. Builder rule block, "MapRoulette" tool. Seeded quest "Clear a MapRoulette task". See `documentation/quest_types.md`, `harvesters.md`. |
